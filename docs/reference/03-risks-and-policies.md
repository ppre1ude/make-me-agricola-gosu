# 03 Risks And Policies

## 저작권과 데이터 사용

### 카드 이미지

카드 이미지는 저작권 리스크가 크다.

초기 정책:

- 직접 카드 이미지를 저장하지 않는다.
- placeholder 또는 텍스트 렌더링으로 시작한다.
- 이미지가 필요하면 출처, 허락, 라이선스를 확인한다.

### 카드 텍스트

카드 효과 전문도 저작권 대상일 수 있다.

초기 정책:

- 개인 개발/비공개 단계에서는 raw를 보관할 수 있지만 공개 서비스에는 주의한다.
- 출처를 명시한다.
- 가능하면 카드명, 태그, 요약, 해설, 외부 링크 중심으로 시작한다.
- 전문 제공은 라이선스와 허락을 검토한다.

### 외부 사이트 데이터

Agricola Cards, ReedStoneFood, BGG, Play-Agricola 등의 데이터는 무단 복제하지 않는다.

정책:

- UI와 구조는 참고한다.
- 데이터 사용은 허락 또는 라이선스를 확인한다.
- 공개 API가 있더라도 요청량과 이용 조건을 확인한다.

## BGA 공정성

서비스는 보조 도구이지 부정행위 도구가 아니다.

제공 가능:

- 공개 카드 정보 검색
- 사용자가 본 드래프트 카드 기록
- 스크린샷에 보이는 카드명 인식
- 카드 통계와 메타 설명
- 사후 복기
- 전략 학습

제공하지 않음:

- 숨겨진 정보 추론
- 상대 손패 자동 추정
- BGA 비공개 데이터 수집
- 자동 액션 선택
- 자동 플레이
- 클라이언트 조작

### 드래프트 메모리 경계

Draft Memory Coach는 사용자가 실제로 본 카드와 직접 입력한 선택만 사용한다.

허용:

- 현재 visible pack 기록
- 내가 고른 카드 기록
- 내가 본 뒤 넘긴 카드 기록
- ADP와 seen-card memory 기반의 확률적 return likelihood
- "이 역할 경쟁이 생길 수 있음" 수준의 불확실한 전략 신호

금지:

- 상대가 어떤 카드를 집었다고 확정 표시
- 숨겨진 pack을 자동 추론
- BGA 클라이언트 내부 상태 접근
- 자동으로 최적 액션을 선택하거나 클릭

추천 문구는 아래처럼 확률적으로 표현한다.

```text
이 카드는 ADP상 돌아올 가능성이 낮습니다.
이 역할의 카드가 이미 지나갔기 때문에 다음 픽에서 경쟁이 생길 수 있습니다.
```

아래처럼 표현하지 않는다.

```text
2번 플레이어가 이 카드를 가져갔습니다.
다음 라운드에 상대가 반드시 화로를 갑니다.
```

## 통계 해석 리스크

Lumin_S 통계는 강력하지만 완전한 진실은 아니다.

가능한 편향:

- 강한 플레이어가 선호하는 카드 편향
- 플레이된 카드만 집계되는 편향
- 특정 ELO 이상 표본 편향
- 4인플 기준 편향
- 카드 풀과 기간에 따른 메타 변화
- 조건부 카드의 과소/과대평가

표시 정책:

- 통계 출처와 날짜를 표시한다.
- playerCount, minElo, cardPool 조건을 표시한다.
- 카드 상세에서 통계를 절대적 평가가 아니라 참고 지표로 설명한다.

## 추천 로직 리스크

추천 점수는 실전 판단을 보조할 뿐 자동 정답이 아니다.

정책:

- 추천 이유를 항상 표시한다.
- 점수 구성 요소를 투명하게 보여준다.
- 조건부 카드에는 리스크를 표시한다.
- 사용자가 직접 수정하고 판단할 수 있도록 한다.

추가 정책:

- score component를 숨기지 않는다.
- 통계 기반 추천과 수동 전략 프로필 기반 추천을 구분한다.
- confidence가 낮은 카드에는 "데이터 부족"을 표시한다.
- deep 설명에서도 단정 대신 조건부 문장으로 쓴다.

## 전략 프로필 리스크

수동 self-tagging은 이 프로젝트의 차별점이지만 편향과 유지보수 리스크가 있다.

가능한 편향:

- 작성자의 플레이 스타일 편향
- 특정 ELO/메타에서만 맞는 평가
- BGA Arena 카드 풀 변화 반영 지연
- broken/plan anchor 태그의 과잉 부여
- 콤보를 과대평가하고 기본 운영을 과소평가하는 문제

대응:

- CardStrategyProfile에 confidence와 sourceRefs를 둔다.
- 최소 50~100장부터 시작하고 전체 A~E 완성을 v0 조건으로 두지 않는다.
- fixture로 추천 결과를 검증한다.
- 통계와 수동 판단이 충돌하면 UI에서 충돌 자체를 설명한다.

## 다국어 확장 리스크

언어별 카드명과 카드 텍스트는 단순 번역이 아니다.

리스크:

- BGA 번역명과 공식 번역명이 다름
- 중국어 간체/번체 차이
- 판본별 카드명 변경
- 팬 번역 alias 혼재

대응:

- Card와 CardTranslation 분리
- locale별 alias 관리
- officialName, bgaName 분리
- 표시 이름 우선순위 정의

## 유지보수 리스크

혼자 개발하는 서비스이므로 자동화가 중요하다.

대응:

- raw, normalized, manual 데이터 분리
- import script 유지
- validation script 유지
- 수동 입력은 JSON으로 관리
- DB는 source of truth로 두지 않음
